1. Public compute-device test: no useful Neural Engine switch
Both phones list only neuralEngine for the revision2 main stage. Legacy body
lists neuralEngine, GPU and CPU. Generic VisionRequest access works on-device;
direct concrete-type access failed compilation. Automatic assignments report
unspecified; we do not claim to trace the actual hardware of all pipeline stages.

                         iPhone11        iPhone17

Automatic and explicit ANE produced identical body outputs in all27 paired

The fixed-image set includes empty detections and different OS versions;
it cannot establish that the newer model is globally faster or more accurate.

2. Cache is effective; first requester is not the same as removable work
Example IMG8606, iPhone11 baseline repeat1:
2,848 body-pose lookups;455 new inferences;2,393 cache hits (84.0%).
455 unique inferred frame IDs: no duplicate inference on the same frame.
First-request attribution:365 ground,86 foot,3 holding,1 body.
Ground is therefore80.2% of first calls, but only101/455 frames were requested
exclusively by ground. Most are also requested by foot, holding or other checks.
Removing ground requests alone would move many calls to a later consumer.
Across successful audited runs, ground-exclusive demand is about18–26%.
Holding-only requests were0–5 frames, so skipping the holding window would save
very little inference in these two clips while risking holding false counts.

The iPhone11 baseline without detailed workload logging averaged19.14ms per
pose, compared with19.19/19.28ms with it. Counts vary across repeated live-paced
runs (e.g.34/36/37 legal IMG8606 contacts), so this is not a proof of zero
instrumentation impact or stable accuracy. Exact numeric replay confirms only
that each saved evidence stream reproduces its own decisions.

3. Person-image warmup explains much of the first-request spike, not throughput
The existing warmup uses a black image. Every measured iPhone11 revision2
failure in the initial workload experiment had its maximum on the first actual
pose request. An explicit lab-only ablation warmed the SAME retained request
with two passes of a staged person image before the replay clock started.
Those pixels never enter the contact cache, video track or counter.

Worst request during replay, black warmup -> additional person warmup:
IMG8606: iPhone11 322.94 ->77.78ms; iPhone17 87.12 ->23.29ms.
IMG8874: iPhone11 349.30 ->78.72ms; iPhone17 70.61 ->20.79ms.
The cost moves into preparation (roughly350ms extra on11,60ms on17 for this
image). Both iPhone11 clips STILL overflowed after person warmup. Its ongoing
pose cost remained approximately48–53ms/call. iPhone17 completed both.
This is an artificial warmup experiment, not a shipped live-preview solution.
Accuracy on IMG8606 fluctuated, and its false ground bounce remained. Any real
preview-frame warmup needs its own integration and regression validation.

4. Accuracy remains a separate blocker
On iPhone17, revision2 automatic recovered all24 labelled kicks in IMG8874
in both build14 repeats and both build15 warmup arms. Explicit ANE returned
24 and23 in its two build14 repeats; it is not a better accuracy setting.
IMG8606 revision2 still counted the known false ground bounce at20.176s in
all completed revision2 arms. Legacy comparisons did not count this bounce.
Faster execution does not remove the previously measured body/ground-rule
regressions. The separate imported-video19versus live-replay24 discrepancy
has not been changed by this work.

Decision / next experiment
Keep revision2 as a test option; do not promote to the main app from this audit.
Do not disable holding checks, increase the32-item queue, or enable holistic
hands globally as a performance workaround. No supported faster compute
assignment was found for revision2.
Next test should coordinate timestamp selection across ground, foot and
holding checks so they reuse a smaller set of actual same-frame ball/pose
samples. Aim to test12–15 unique requests/second, not assume it will be safe.
First evaluate candidate sample schedules offline on saved evidence, including
all known ground/hand/holding negatives and legal low touches. Then run fresh
Vision comparisons on both phones and longer sessions. Warm a real preview
person frame separately if that experiment preserves accuracy; do not retain
the staged-image shortcut in a release.

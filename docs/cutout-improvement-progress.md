# Sequential cutout and scene improvement

The newer `vitmatte-small-768-r3` player changes and input11 comparison are documented in [input11-cutout-improvement.md](input11-cutout-improvement.md). The experimental ball workarounds were subsequently removed at the user's request; see the [detector-versus-pipeline findings](../artifacts/input11-model-boundary/REPORT.md). The phone installation and export evidence below belongs to the earlier r2 build; r3 was validated locally on the Mac and in simulator tests.

User constraint: the source grass hides parts of the foot. Preserve the actually visible shape and do not reconstruct hidden toes. Separate that source limitation from mask defects and floor placement.

1. Stage trace and earliest mask failures — complete for the current park clip. Full 212-frame preparation traced; 374 lossless snapshots across consecutive hand/hair failure windows. Foliage is present in raw subject lifting before cleanup. Both plain and confidence-weighted MPS guided filtering spread additional faint background and are rejected.
2. Fine-detail refinement — **selected main path: native Vision target selection → disagreement-aware trimap → ViTMatte Core ML person refinement, plus the existing independent ball branch.** Native and 768-square trials cover 34 consecutive-window captures. RVM is compared on person ROIs; full-frame still comparisons share the captured ball masks. It remains a useful benchmark, not a rejected person model merely because it omits a detached ball. The converted Core ML model's mean alpha error versus the fixed-size PyTorch run is below 0.00037 on four frames (maximum below 0.0084). The integrated Swift path also changes resampling and trimap rounding; its parity is documented separately, not described as bit-identical. The model adds about 54 MiB to the app; conversion, fixed checkpoint provenance and upstream notices are checked in. Phone preparation succeeds with no missing person/ball flags on the park clip.
3. Temporal consistency — found and fixed a concrete history leak: low-opacity history could pass alpha agreement in otherwise empty current-mask areas. A current-support gate eliminates that unsupported haze (253,106 to zero pixels across the 34 captured frames, measured outside a two-pixel mask neighborhood). This metric describes that specific defect, not segmentation accuracy. The indoor camera-whip tail exposed another issue: a confident but incorrect guide could yield an entirely weak learned matte. The final estimate now needs a small confident core; small opaque partial people remain eligible. The final 572-frame indoor run verifies zero person and final alpha in the previously leaking frames 547, 549 and 551. The small opaque partial-person fragment at frame 149 remains. This gate deliberately rejects entirely weak estimates and is not proof of universal partial-person recall.
4. Export quality/cache — the old encoded alpha had mean absolute error 0.00121 overall and 0.00794 on soft edges, maximum 0.15686. Alpha now uses a separate LZFSE lossless cache, indexed by decoded color timestamps. Both interactive preview and scene export use it; damaged/mismatched caches fail explicitly. Backward-seek and shader-layout tests cover the new path. Real round trips have **zero mismatches** across 42,985,384 sampled alpha values at 30 fps and 41,713,920 at source cadence. All 422 decoded color frames find their matching masks. The final indoor run also has zero mismatches across 114,048,000 alpha values from 55 saved frames, and all 572 decoded frames match the alpha cache. Preparation and calibration now retain nominal source cadence up to 60 fps; the user's 59.94 fps clip produces 422 frames instead of 212. Slow-motion/VFR source-frame identity is not claimed universally. The final effects pass previously resampled scene frames; prepared upright SDR scenes now keep their actual timestamps, including resolution changes. Video writers use a 60,000-unit time scale. A variable-cadence regression test covers this failure.
5. Visible-foot placement and scene integration — accepted downward contact now updates the floor immediately, preventing low-pass lag from placing the visible boundary below it. Abrupt lost-foot rejection and conservative upward filtering remain. Actual phone output measures at most 1.82 rendered pixels below the anchor (0.366 virtual cm assuming a 1.75 m person), with no frames over 1 virtual cm. These are rendering measurements, not physical reconstruction. Arena reflections now soften with height above the contact and have a slightly reduced strength. A blanket exposure trial was removed; it was not evidence of true scene relighting and conflicted with keeping the Original color look. Preview and export share the same reflection shader.

Evidence is under `artifacts/cutout-final-pass/`. Diagnostic callbacks are opt-in; normal preparation does not write stage images or run the spatial-only probe.

## Verification and limits

- 63 app tests pass, including actual Metal compositing, lossless alpha/seek integrity, partial-person eligibility, foot-contact lag, and exact export timestamps at a different output resolution.
- The final actual-iPhone run uses `vitmatte-small-768-r2` and produces 422 frames with 422 lossless mattes; all have person and ball flags. Every frame interval is exactly 1001/60000 seconds and the mask-index timestamps match exactly. The alpha sidecar is 19,073,565 bytes for this clip. See `iphone-complete/verification.json` and `phone-contact-complete.json`.
- The app's real simulator playback and save-to-device workflow is verified using the final actual-phone cache. All 422 frame timestamps match exactly through foreground cache, rendered scene and exported effects video (last frame 7.023683 seconds). The original AAC packet payload SHA-256 is unchanged. See `app-export/final-export-verification.json` and its provenance file. The app displays “Saved Edited to Photos (1080p).”
- Residual green edge-color spill around hair/clothing and uncertain fine details remain visible in the actual arena export. These are not claimed fixed by the exact-cache or timestamp tests. There is no hand-labeled ground truth, independent held-out benchmark, or measured oldest-device memory/runtime budget yet. Soft-source motion blur and anatomy hidden by grass cannot be recovered by this pipeline.
- The scene still uses a flat foreground plane and source-baked illumination. Reflections and contact help integration, but this is not a depth/normal reconstruction or physically correct relighting system. Do not describe it as universally photorealistic.

Review the [final arena scene without the counter](../artifacts/cutout-final-pass/app-export/arena-scene-final.mp4), or the [actual saved export including the existing counter](../artifacts/cutout-final-pass/app-export/arena-export-final.mp4). The saved export is generated by the real app workflow, not a separately assembled research composite. The final development build is installed on the connected iPhone.

The next unresolved quality priority is foreground-color recovery at contaminated edges, judged separately from alpha coverage. The current local foreground/background fit still leaves visible green fringes. Additional candidates need consecutive-frame comparisons on hands/hair and a held-out clip before adopting them; a global green removal or stronger erosion would risk changing clothing and removing real detail. Lighting/depth integration remains a separate scene problem after edge cleanup.

## Reproducible evidence

- `scripts/trace-cutout.swift`: shared native processing, opt-in lossless stage captures; defaults to the established 30 fps diagnostic reference, optional final argument 60 for source cadence.
- `scripts/compare-guided-matte.swift`: plain and confidence-weighted MPS experiments; rejected visually.
- `scripts/compare-trimap-matte.py`, `convert-trimap-matte.py`, `check-trimap-coreml.py`: pinned learned-refiner experiment and conversion checks. Isolated Python environment uses Transformers 4.57.6, Core ML Tools 9.0, NumPy 2.2.6; exact torch version is recorded in conversion provenance.
- `scripts/compare-cutout-windows.py`: person-ROI stability proxies and same-ball still comparisons. RVM used a compressed SDR crop, so that comparison is not a ground-truth accuracy score or fully identical input decode.
- `scripts/verify-lossless-alpha.swift`: exact saved-alpha comparisons, backward reads, and every decoded color PTS.
- `scripts/audit-ground-contact.swift`: contact against lossless alpha when available.
- Model source: [published checkpoint](https://huggingface.co/hustvl/vitmatte-small-composition-1k), revision `6a58ad7646403c1df626fbd746900aec7361ea1d`. Runtime uses Core ML locally; Python and the research runtime are not bundled.
